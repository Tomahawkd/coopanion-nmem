## 目标（一个内聚行为）

Coo 能通过本 World 的 `nmem_*` 工具**读**（搜索/读取 Mem 记忆）与**写**（沉淀新记忆到 Mem），并由 ENV_PROMPT 引导调用时机与内容质量。

## 范围

1. `src/tools.ts`：`NMEM_TOOL_DECLS` 三工具（architecture.md §1.4）——`nmem_search`（read；query 1..500、limit 1..10 缺省取 cfg、mode fast|deep 缺省取 cfg）、`nmem_get`（read；404 → 明确「未找到」）、`nmem_save`（write；content 1..30000 超限返回 failed 明确文案不截断；`id?` ≤200 upsert；`title?`/`unit_type?`/`labels?`/`importance?`；默认并入 label `coopanion`；溯源字段 source/source_app/agent_id=ctx.botName）。
2. `src/world.ts` 接线：`create(ctx)` 构造 `MemClient` 注入；handler 现读 `ctx.cfg`（热改生效）；**负责 client↔world 集成**（T2 交付后接入真实 client，此前用 fake client 开发）。
3. `src/ENV_PROMPT.md` 全文（英文，模型文本）：何时 `nmem_search`（涉及用户事实/偏好/历史时、开场可探一次）、何时 `nmem_save`（值得长期保留的事实/偏好/决定；更新既有记忆先 search 拿 id 再 save）、**PARTNER.md 并行写策略（D10：照常维护 PARTNER.md，同时另存 Mem）**、工具失败时简短告知用户并继续（不重试轰炸）、单条记忆保持精炼（≤30000）。
4. `describe.json` 更新：`describeTools(NMEM_TOOL_DECLS, {zh,en})` 同步生成并提交。
5. 测试：`tests/tools.test.ts`（参数校验、回执格式、upsert 回执含 id 与 action、溯源透传、失败文案）+ `tests/world.test.ts` 扩展（describe 与提交文件一致、cfg 热改 searchLimit 生效、start 事件）。

## 成功与失败示例

- 成功：dryMountWorld 零失败（含工具名冲突检查）；`nmem_save` 回执含服务端 id 与 `action:created|updated`；fake client 注入下全工具单测绿；describe 一致性测试绿；门禁绿（含「仅 client 拥有网络传输」边界——工具层无 `node:http`/`undici`/`axios` import）。
- 失败示例（应被发现并修复）：content 超限被静默截断（须 failed 回执）；`envPromptVars()` 里做 Mem I/O（§2b 禁止）；回执无界（须截断 ~200 字符/条、上限 10 条）；错误抛裸异常致文案不可控（须 `failed:true` + 可行动文案）；工具名与保留帧/内置 World 冲突。

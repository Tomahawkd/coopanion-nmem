## 目标（一个内聚行为）

一个**类型化、框架无关、可独立单测的 Nowledge Mem REST 客户端**（`src/mem/{client,types}.ts`）：传输/鉴权/超时/重试/错误分类/ingress 类型收窄的唯一所有者。

## 范围

1. `src/mem/types.ts`：请求/响应契约的具体 TS 类型（`MemoryHit[]`、`MemoryRecord|null` 等）；按端点收窄（search 裸数组 / get 裸对象 / 列表 `{memories:[…]}`，R4）；search 元素 `memory` 可为 `null`。
2. `src/mem/client.ts`：`MemClient`（构造注入 `{baseUrl, apiKey?, transport?}`，transport 缺省全局 `fetch`——测试缝，不用 mock 库替换全局）。行为矩阵（architecture.md §2f）：无 key 不发鉴权头 / 有 key 发 `Authorization: Bearer`；401 不重试；429 单次退避重试（`Retry-After` 或 1000ms）；502/503/504 单次重试 500ms；超时 10s `AbortController`；坏 JSON → `MemProtocolError`；get 404 → `null`。
3. 方法面（仅三个 + 探活）：`searchMemories`、`getMemory`、`saveMemory`（`id` 可选 upsert；服务端溯源字段 `source:'coopanion'`/`source_app:'cortico-world-nmem'`/`agent_id` 由工具层传入，client 只透传）、`health`。
4. `tests/mem-client.test.ts`：注入 fake transport 的完整行为矩阵（离线）。
5. 关闭 architecture.md §7 缺口 4：实测 `JSON.stringify` 请求体出口是否触发门禁 `type.broad`；触发则按 checker-configuration.md 加 reviewed encoding outputs 声明（属策略变更：全量审计 + 经用户带回 architecture 审查，不得绕过）。
6. 观测并记录缺口 7 相关信息：本机 deep 模式延迟（信息性，供 10s 超时常数校正；改常数在本组内允许，不加旋钮）。

## 非目标

## 组间契约与依赖

- 前序：T1（骨架与门禁）。**与 T3 可并行开发**：接口契约以 architecture.md §1.4/§2f 为准冻结，`types.ts` 优先完成作为 seam；client↔world 集成归 T3。
- 补充约束（T1-R2 条件 C2，2026-10-26）：热改键不得在构造期快照；`MemClient` 仅接收非热改参数（baseUrl/apiKey，create() 时传入），热改项（searchLimit/searchMode）由调用方现读 `ctx.cfg`；禁读磁盘 config.json。

## 成功与失败示例

- 成功：行为矩阵单测全绿；门禁绿（含「mem client stays framework-agnostic」边界——`src/mem/*` 无任何 `cortico` import）；无 key 请求的字面不含 Authorization 头（单测断言）。
- 失败示例（应被发现并修复）：恒发空 key 头导致本机 401（R2）；对 401 自动重试触发 429 限流（R3）；把 search 响应当 `{items:[…]}` 解析抛错（R4）；超长 content 静默截断（须由调用方校验拒绝，client 不截断）。

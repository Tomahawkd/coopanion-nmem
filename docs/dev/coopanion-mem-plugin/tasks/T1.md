## 目标（一个内聚行为）

一个**可安装、可挂载的最小 Cortico World 包**（`cortico-world-nmem`，`kind: world`、`api: 6`、`type: module`、零运行时依赖，license MIT）在本仓库就位，且工程门禁（TypeScript 工具链 + codeharness 策略）全部可运行。

## 范围

1. 仓库脚手架：`package.json`（含 `cortico` manifest、devDependencies：`cortico ^0.2.7`/`tsx`/`typescript`/`vitest`/`@types/node`、`files` 白名单、MIT）、`tsconfig.json`、`vitest.config.ts`、`pnpm-lock`（用 pnpm 安装）。
2. World 骨架：`src/{index,definition,config,world}.ts`——0 个工具 + `nmem.started` 事件（`origin:'internal'`）+ 全量配置段（`worlds.nmem.{enabled,baseUrl,searchLimit,searchMode}`，`enabled` 默认 `false`）+ `ConfigGroup`（`x-hot` 按 architecture.md §2e）+ `ENV_PROMPT.md` 占位 + `describe.json`。
3. 工程门禁：本仓库 `.codeharness/code-harness.json`（按 architecture.md §4.1 草案，含 §7 缺口 3 的实测校正）与 `AGENTS.md`（§4.2 八条）。
4. codeharness 环境同步（**授权动作，源自用户裁定 D5①**）：在 `../codeharness` 执行 `uv sync --locked --group dev`（使用其 README 的清华镜像安装指引）。该目录已存在一个空的 gitignored `.venv/`（设计期副作用，保留即可）。
5. 关闭 architecture.md §7 缺口 2/3/5：实测 `pnpm check:extension`/`describe:extension` 第三方可用性（不可用则以单测替代并记录）；实测 `third_party_modules` 对路径形 specifier（`cortico/core/types.ts`）的匹配（必要时精确列举）；sideload 后确认无面板时 ConfigGroup 旋钮在设置界面的实际呈现。
6. 测试骨架：`tests/helpers/fake-host.ts`（照 cortico 模板适配）、`tests/world.test.ts` 骨架（dryMountWorld 零失败、`enabled:false` 默认、start 事件断言）。

## 成功与失败示例

- 成功：`pnpm typecheck`、`pnpm test`、`code-harness --root <本仓库> --all` 三者全绿；本机 Extensions 页 local 安装本仓库目录 → Restart process → World 总览可见 `nmem`（默认禁用）→ 启用后事件流出现 `nmem.started`。
- 失败示例（应被发现并修复）：`type` 非 module 被拒载；工具名冲突拒绝挂载；门禁 include 漏文件导致空审计报错（codeharness 规则：空全量审计是错误）；旋钮路径落在 `worlds.nmem.*` 段外被 dry-mount 校验拒绝。
